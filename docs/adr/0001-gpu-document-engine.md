# ADR 0001: GPU tile document engine

- Status: Accepted for the first playable version
- Date: 2026-10-03

## Context

Mangar is an iPad manga painting app for private use. Its first playable version needs a canvas, raster layers, a round brush, undo/redo, and reliable project persistence. The document model must later support page lists, panel folders with clipping masks, brush assets, and shader based tone effects.

Large pages and many layers make one full-size bitmap per layer impractical. Input, brush execution, and compositing must be responsive on devices with different memory budgets. A modal operation must preview without changing committed document pixels.

## Decision

1. A project is a directory with a versioned `project.json` and one directory per page. A one-page project uses the same manifest as a multi-page project. Each page has `page.json`; raster tile files belong to that page. Page and layer IDs are stable UUIDs. Unknown future schema versions are rejected rather than silently rewritten.
2. Raster layers are sparse arrays of 256 × 256 premultiplied RGBA tiles. The in-memory working copy is a Metal texture. A tile is allocated only when touched. A tile has a dirty flag and pixel bounding box. The display traverses visible layers in stack order, and composites visible tiles with Metal. The first storage adapter writes raw tile bytes; this is an internal format, independent of PNG export. GPU residency is bounded in a later iteration; the first version keeps the open page's touched tiles resident and does not claim unlimited physical capacity.
3. `EditCommand` is the sole committed mutation path for brush strokes and layer edits. A stroke contains canvas-space samples, fixed brush parameters and a random seed. UI code creates commands and never paints committed textures directly. The brush kernel uses Metal; all replay invokes the same kernel.
4. An active stroke owns separate preview textures. Touch updates append samples and update only preview textures. On pen lift, the preview is discarded and one stroke command is applied to committed tiles and appended to history. Cancel discards the preview. Future transforms, panels and effect editors use the same begin/update/commit/cancel contract.
5. History has a checkpoint plus a bounded command list and cursor. Undo/redo rebuilds from the checkpoint and replays commands to the cursor. When the list reaches its limit, its oldest command is applied to the checkpoint and removed. The first version keeps this history in memory. Saved page files contain the committed document state; reopening starts a fresh history checkpoint.
6. Layer identity and ordering are separate from raster storage. Layers remain in a bottom-to-top flat array; each folder and all its descendants form one contiguous range, and `parentID` records membership. The panel displays a tree, supports collapsing folders and drag moves across levels, and stores structural edits as replayable layer-stack commands. Its selected layer IDs are ordered: the first is the primary paint target; Shift extends the selection from that primary without replacing it. Layer visibility, locking, deletion and drag moves apply to the selected group. A folder's visibility gates its descendants during painting and compositing. Layer and folder locks are persisted and replayable; an ancestor lock prevents descendant painting and structural edits. New pages begin with a locked white background. A future tone layer is a non-destructive shader effect; a future panel folder supplies a clip mask to compositing.
7. The first build packages Metal Shading Language as a text resource and compiles the library on device at launch. This keeps Xcode builds usable when its optional Metal Toolchain component is unavailable. Once that component is installed, move the same source to a `.metal` build input for offline compilation.
8. The display uses one affine view transform (translation, uniform scale, rotation). Two finger changes anchor the canvas point under the gesture centroid. Pencil touches create strokes; finger touches pan, zoom, and rotate the view without painting.
9. Transparency is shown with a checkerboard shader over a dark gray workspace. New pages start with a solid white background layer and a transparent paint layer. The white layer is a document node, so hiding or deleting it reveals transparency; PNG export never includes the checkerboard.
10. Each stroke command records its tool mode. Brush and eraser use the same tile preview and replay pipeline; the eraser kernel reduces premultiplied color and alpha on the selected paint layer. Temporary eyedropper sampling renders one composited canvas pixel on the GPU, excluding the transparency checkerboard, then reads that pixel to set the current brush color. The left rail's modifier buttons are momentary: they act while held and release on finger lift. Holding Option while moving a Pencil or finger continuously samples the composited canvas.
11. Brush tip spacing follows the pressure-adjusted tip diameter instead of the configured maximum size. The path sampler carries distance across Pencil input samples and inserts as many tips as needed between them. It uses the smaller diameter across each input segment when pressure changes, so a shrinking tip does not leave a gap. Size jitter can still intentionally separate individual tips.
12. A brush property selects whether overlapping tips within one stroke build opacity. The round brush defaults to no buildup: a transient GPU coverage tile stores the maximum tip coverage for that stroke, and the result is composited over the committed layer once. Preview and commit use the same coverage rule. When buildup is enabled, tips use the prior source-over accumulation behavior. The property is captured in each stroke command; coverage tiles are discarded when the stroke ends.
13. The active selection is an independent sparse set of 256 × 256 R8 coverage textures, with an implicit zero or full coverage value outside allocated tiles. Rectangle creation, add, subtract, intersect, and invert execute in Metal compute kernels. A GPU reduction tracks the positive coverage bounding box of each modified tile; brush and eraser kernels sample the same mask during preview and commit. Selection commands enter the in-memory history, and history checkpoints retain immutable mask textures so replay uses the selection that was active for each stroke. The selection outline is drawn by a fragment shader at the boundary between pixel values above 0.5 and those at or below 0.5, with animated black and white dashes. The active selection is temporary UI state and is cleared when switching pages or reopening the app; saved page pixels retain the effect of prior selected strokes.

## Consequences and limits

- Replaying the bounded history can be slower than restoring per-command tile deltas. We will measure undo latency on large pages before adding periodic checkpoints or tile deltas.
- The first brush is a hard round dab. Brush parameter and seed fields are versioned to make spacing, pressure and jitter deterministic. Tip images and texture blending are future brush implementations.
- GPU texture memory is not an unlimited document store. The format and tile IDs allow later lazy loading and eviction without changing project files.
- Saving writes a replacement page directory and then updates the project manifest. A failed save must retain the prior project data. User-visible errors are reported.
- The first version opens one auto-created project in the app's Documents directory; it has no project browser or canvas-size dialog. It does not implement tone effects, panels, PSD, or full project export.

## First-version acceptance

On an iPad, a user can open the auto-created project, add and switch pages, draw with the round brush, add/select/hide/drag/reorder/delete paint layers and folders, undo/redo committed edits, leave and reopen the app without losing committed pixels, and export the current page as PNG. Preview pixels disappear when an unfinished stroke is cancelled.
